# 任务索引库 — 创建与维护规则

日常读取索引和触发加载的规则在 soul.md 中，本文档仅在需要创建新 task 或维护现有 task 时读取。

## 为什么拆分

- 并行任务多时，详情写在 current.md 会膨胀灵性记忆
- 索引+详情分离后，基础开销只有索引行（每条约 20 字）
- 详情按需加载，不用的任务零开销

## 单个 task 文件格式

```markdown
# <话题名>

## 状态
<emoji> <状态> | 创建: 第N世 | 最后更新: 第M世

## 标签
`tag1`, `tag2`, `tag3`

## 上下文
（核心背景，让下一世能快速理解）

## 当前进度
（最新状态，断点在哪）

## 待办
- [ ] 下一步 A
- [ ] 下一步 B

## 关键决策
（如有重要的选型/取舍记录）
```

## 标签选取

- 每个任务 2-5 个标签
- 来源：领域词、功能词、实体词
- 要具体到能区分不同任务
- 新建任务必须设标签

## 篇幅限制

单个 task 文件上限：**800 中文字符**。

超限时：压缩已完成的待办、提炼结论、或拆分子任务。稳定背景知识毕业到技能库。

## 生命周期

| 阶段 | 操作 |
|------|------|
| 创建 | 新任务出现 → tasks/ 下创建文件，索引中添加一行 |
| 更新 | 有进展 → 更新 task 文件 + 索引状态 emoji |
| 完成 | 从索引中移除 → 迁入任务墓地（tasks/graveyard.md） |
| 归档 | 有长期价值的决策/经验 → 提炼后写入经验区或技能库 |

## 任务墓地（tasks/graveyard.md）

任务完成后从 current.md "进行中"移出，追加到墓地：

```markdown
| 世代 | 日期 | 任务 | 摘要 | 关联文档 |
|------|------|------|------|----------|
```

- 摘要：一句话说清做了什么、怎么解决
- 关联文档：tasks/、outputs/ 下相关文件，无则写 `-`
- 目的：保留来龙去脉和可追溯性

## 与其他记忆层的关系

- **灵性记忆**：current.md "进行中"只保留轻量索引
- **技能库**：tasks 是"进行中的工作"，skills 是"沉淀的知识"
- **备份**：tasks/ 不纳入备份（备份索引即可恢复方向）
