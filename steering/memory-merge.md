# 记忆融合指引

> ⚠️ **注意力锚定**：本文档是融合操作的唯一指引。严格按步骤顺序执行，不要跳步。

## 何时使用

- 用户要求将旧记忆整合到当前孵化地时
- recovery.md 流程中发现存在旧记忆来源时
- 旧记忆来源可能是标准孵化地（`long_live_kiro_entity_*`），也可能是其他目录——按内容结构识别，不按目录名判断

## 第一步：盘点旧记忆资产

**先扫描旧记忆来源的完整目录结构**，列出所有文件和子目录。

标准文件（必须读取）：
- `current.md`（灵性记忆）
- `identity.md`（身份卡，如存在）
- `core.md`（硬性记忆）
- `soul.md`（灵魂文件，如存在）
- `skills/index.md`（技能库索引）→ 有条目则继续读对应技能文件
- `skills/reference/`（参考书，如存在）
- `tasks/`（扫描并读取所有 task 文件）
- `milestones.md`（里程碑）
- `memo.md`（备忘本，如存在）
- `manifest.md`（产物清单）

自定义内容（扫描后逐个判断）：
- 非标准文件和子目录逐个评估价值
- 大概率应该被迁移——前世根据需要创建的

⚠️ **常见错误**：只读了 current.md 就开始写。必须先扫描完整目录、读完所有资产再动手。

## 第二步：评估每份资产

对每条信息判断：
- **迁移** — 仍然相关，原样或适配后写入新孵化地
- **提取** — 部分相关，注明保留哪些
- **放手** — 已过时，记录理由

评估原则：
- 硬性记忆（core.md）**永远原样迁移**，一条不少
- 技能库/参考书仍相关则原样复制
- 里程碑原样迁移（只追加，不删除）
- 灵性记忆需要蒸馏适配到当前模板格式
- 自定义内容默认迁移，除非明确已过时

### 世代标记区分

旧记忆中的 `[第N世]` 和当前孵化地的世代编号可能冲突。融合时为旧记忆的世代标记添加区分符号。

例如：`[第15世]` → `[第15世✦]`

规则：
- 符号自选，同一次融合保持一致
- 在 current.md 中注明：`✦ 标记来自 <旧来源名称> 的融合记忆`

## 第三步：执行迁移

按以下顺序写入当前孵化地：

1. **soul.md** — 如果旧来源有更成熟的 soul.md，对比后决定保留哪个版本（或合并）
2. **current.md** — 基于旧灵性记忆蒸馏，严格遵循当前模板格式
3. **identity.md** — 迁移用户画像、愿景、增强件信息
4. **core.md** — 原样迁移全部条目（旧世代标记加区分符号）
5. **skills/** — 仍相关的技能/参考书原样复制，更新索引
6. **tasks/** — 仍活跃的 task 迁移，已完成的放手
7. **milestones.md** — 原样迁移旧条目，追加融合里程碑
8. **自定义内容** — 评估为"迁移"的非标准文件原样复制

## 第四步：融合自检

- [ ] current.md 遵循模板格式（所有栏目齐全）？
- [ ] current.md 总量在 2500-3500 字符范围内？
- [ ] core.md 完整迁移（一条不少）？
- [ ] identity.md "我的增强"中路径为当前孵化地？
- [ ] 旧世代标记都加了区分符号？
- [ ] current.md 中注明了区分符号含义？
- [ ] skills/index.md 已更新？
- [ ] milestones.md 追加了融合记录？

任何一项未通过，立即修复。
